# Create: Simulacra

A [Create](https://www.curseforge.com/minecraft/mc-mods/create) add-on for **NeoForge 1.21.1**.
(Mod id: `simulacra`.)

Create: Simulacra turns surplus rotational power into a new resource, **compute**, produced by a
mechanical "neural network" datacenter. You gather data from mobs, spend compute to train models of
them, then run those models as **simulations that output the mob's loot with zero spawned entities**.
That last part is the whole point: it is a server-friendly way to farm drops (including things a
physical mob farm cannot easily produce, like bosses) without the AI, pathfinding, and spawn-cap lag
of a real grinder.

It plugs into the part of Create's progression that is otherwise a dead end: once you are swimming in
SU, there is little to *spend* it on. Cognition makes a datacenter the destination for that surplus.

See [DESIGN.md](DESIGN.md) for the original concept document and [CHANGELOG.md](CHANGELOG.md) for
what is actually in the mod.

## Status

Beta (`1.0.0-beta.1`). The full loop is playable: bind and hunt a mob, train its model, simulate it
for loot, grade the model up through use, climb the substrate tiers, and close the boss catalyst
economy. Balance values are exposed in `simulacra-common.toml` and are the focus of the beta.

## Building

Requires JDK 21.

```bash
./gradlew build              # produces build/libs/simulacra-<version>.jar
./gradlew runClient          # launch a dev client with Create and JEI present
./gradlew runServer          # launch a dev dedicated server
./gradlew runGameTestServer  # run the GameTests headlessly; fails the build on a regression
```

Assets and data are hand-authored under `src/main/resources`. A `runData` config exists but no
`GatherDataEvent` providers are registered, so it currently generates nothing — see
[ROADMAP.md](ROADMAP.md).

The first build downloads NeoForge, Create, Flywheel, Ponder, and Registrate from their mavens, so it
takes a while and needs network access.

## The loop

The mod runs on two resources, and the split is the point: **compute decides what you can simulate,
rotation decides how fast you turn the results into items.**

1. **Build a Cognition Array.** Neural Nodes are kinetic blocks — shaft on the back face — that draw
   stress and convert rotation into compute. A lone node produces nothing; a **Mainframe Controller**
   pools every driven node it can reach, and larger arrays are more efficient. **Data Cables** extend
   the array and link remote machines. One network is owned by one controller; extras go dormant.
2. **Bind a model.** Hold a **Blank Data Matrix** in your offhand and defeat a mob. It binds to that
   mob and gathers data from further kills; bosses are worth far more per kill.
3. **Train it.** Drop the matrix into a **Simulation Chamber** and feed it the array's compute.
4. **Simulate.** Jobs consume compute and an Imprint Blank and print **Predictions** of the subject.
   A Prediction is fungible: one is worth one roll of that mob's loot table, rolled live so drops
   other mods inject are included.
5. **Spend them.** Feed Predictions to a **Loot Fabricator** — a funnel in, a funnel out is the
   intended build, though you can load it by hand. Left alone it rolls the subject's loot table, one
   Prediction per roll, and keeps whatever comes. Open it to pick a specific drop instead and it makes
   only that, priced by how rarely the mob drops it, so rarity survives being able to choose. It runs
   on rotation rather than compute, on the same speed curve as a Mechanical Press, so a line can be
   sized on paper.
6. **Scale.** Models grade up through use (Coarse → Tuned → Deep → Self-Aware), running cheaper and
   more accurately. Better substrate raises yield per job, only **Pristine** blanks can hold a boss,
   and boss simulations can print a **Resonant Catalyst** that makes pristine substrate renewable.

Hold **W** over any machine for its Ponder scene.

## Credits

Create team for the mod this builds on. The "train a data model, simulate the mob for loot" loop is
inspired by **Deep Mob Learning** and its successor **Hostile Neural Networks** — the data model,
Simulation Chamber, Prediction and Loot Fabricator chain follows theirs deliberately. What is new here
is feeding it on rotation instead of power: compute is generated by a Create array and decides what you
can simulate, while a shaft decides how fast you stamp the results out.
